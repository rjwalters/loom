# Park Record Format (`loom:blocked`, Issue #8925)

`loom:blocked` says "waiting on a dependency, but still automatable once that
clears" (`defaults/docs/label-state-machine.md`). Nothing said *which*
dependency in a form a machine can read. A role that applies the label
routinely writes its reasoning as prose, in a comment:

- PR #8314 was parked on #8322 by a Doctor stand-down whose only record was
  *"filed #8322 to track it, standing down"*. Correct reasoning, 155h parked,
  invisible to every automated lane — `guide.md`'s unblock sweep and
  `loom-daemon check-stale-blocked` both read an artifact's **body**, never
  its comment trail.
- Issue #8852 was parked on #8860. #8860 closed; #8852 stayed parked, because
  the only place the dependency was ever stated was a Curator comment.

A **park record** is the fix: one line, in the artifact's **body**, naming
one blocker. `loom-daemon park-record render`/`parse` (below) is the
canonical writer/reader; `loom_daemon::park_record` is the Rust module both
sit on top of.

## The grammar

```
<!-- loom:park Blocked by: #8322 by=doctor at=2026-09-19T12:09:00Z reason="needs an architecture ruling" -->
```

- `<!-- loom:park ` … ` -->` — an HTML comment, so it renders invisibly in the
  rendered issue/PR, and a **sentinel** that distinguishes a declaration from
  prose that merely *mentions* a blocker elsewhere in the body. Same pattern,
  same reason, as the lease record (`<!-- loom:lease host=… sweep=… -->`,
  `lease-record.md`) and the verdict-SHA / `loom:ac-verified` markers. A
  marker quoted inside a fenced code block or an inline code span renders as
  visible text, so it is **not** a record: the parser ignores it and a re-park
  never edits it (#10837, where quoted evidence released an unrecorded hold).
  `park-record retract` (#13895, below) is the tool that applies this rule to
  withdraw a blocker; a body whose records are all demoted declares zero
  blockers to every reader of `park-record parse`/`blockers` — Guide's
  `parse_dependencies` reads them through the same daemon parser for exactly
  this reason.
- `Blocked by: #N` — **deliberately the existing vocabulary**, not a new one.
  `guide.md`'s `parse_dependencies`, `dep_recheck::extract`'s
  `DEPENDENCY_PHRASES`, `warn-operator-gated.sh` and
  `detect-dependency-cycle.sh` already match `Blocked by`. A park record is
  therefore readable by every parser already in the fleet the moment it is
  written, and this format adds no second dependency vocabulary.
- `by=<role>` / `at=<RFC3339>` — provenance, so a park can be attributed and
  aged without reading the comment trail.
- `reason="…"` — optional free text, quoted so it can contain spaces. A
  `"` inside the reason is downgraded to `'`, and a `--` run is collapsed to a
  single `-` — an HTML comment cannot contain `--`, so an un-sanitised reason
  quoting a CLI flag (`--force`) would terminate the marker early and leak the
  rest of the reason into the visible body.

**One record per blocker**, not a comma-separated list — this is forced by the
two parsers this format promises to stay compatible with, which do not agree
on how to split a multi-reference line: `guide.md`'s two-stage
`parse_dependencies` returns every `#N` on the line, but
`dep_recheck::extract`'s single-capture-group regex returns only the first. A
comma-separated record would silently declare only its first blocker to the
second parser — a park that reads as cleared while a real blocker is still
open. `loom-daemon park-record render --blocked-by` therefore emits one line
per blocker when given more than one:

```
<!-- loom:park Blocked by: #8322 by=doctor at=2026-09-19T12:09:00Z -->
<!-- loom:park Blocked by: #8323 by=doctor at=2026-09-19T12:09:00Z -->
```

A hand-written record naming more than one `#N` on a single line is still
tolerated by the reader (`park_record::parse` expands it into one record per
reference) — the one-line-per-blocker rule binds the *writer*, not the parser.

## Who writes one, and when — `park-record apply` (#10152)

**Cross-repo blockers (#10443).** A blocker in another repository is written
`OWNER/REPO#N` (`Blocked by: example-org/tool-repo#202`). `--blocked-by` accepts `N`,
`#N` (this repo) and `OWNER/REPO#N`, mixed and comma-separated; still one record
per blocker. A qualified reference is **never** resolved against the local repo:
`check-stale-blocked` reads its state in its own repo, `apply` refuses a closed
one by looking it up there, and it is a self-block only when it names this very
repo and number. `#9` and `o/r#9` are two distinct blockers. Records written
with a bare number parse exactly as before (`repo` is `None`).

**Every** role applying `loom:blocked` writes one, through one command — never
a bare label edit:

```bash
loom-daemon park-record apply --issue 8852 --blocked-by 8860 --by curator
loom-daemon park-record apply --pr 8314 --blocked-by 8322 --by doctor \
  --reason "needs an architecture ruling" --remove-label loom:treating
loom-daemon park-record apply --issue 8440 --reason operator --by human   # no blocker
```

`apply` reads the artifact fresh, then:

1. **Refuses** (exit 1, nothing changed) when there is neither `--blocked-by`
   nor an explicit `--reason`. A park with no named blocker reads as
   UNDOCUMENTED to `check-stale-blocked`, and is never released automatically — so it must be
   a written choice (`--reason operator`, a quarantine/scope ruling …), which
   renders an attributable `Blocked by: (unstated)` record, never an omission.
2. **Refuses** a blocker that is already closed (#9102) — the unblock sweep
   would release the park at once — and a self-block.
3. Appends one record per blocker the body does **not** already declare in a
   park record (idempotent: re-running changes nothing).
4. Writes the **body first**, then adds `loom:blocked`, then removes each
   `--remove-label` (e.g. `loom:building`). A failed body write applies no
   label, so there is never a label-only park. Exit 4 on any forge failure.

`--dry-run` prints the planned body and label changes. Comment as usual to
explain *why* in prose — the marker is the part a machine can also read.

`park-record render` (below) remains for composing a body by hand; a park
record has no positional requirement in the body.

```bash
loom-daemon park-record render --blocked-by 8322 --by doctor \
  --reason "needs an architecture ruling"
# <!-- loom:park Blocked by: #8322 by=doctor at=2026-09-19T18:04:11Z reason="needs an architecture ruling" -->
```

### The daemon's own holds (#10161)

Two `loom:blocked` writers live inside `loom-daemon`, not in a role prompt: the
insta-crash quarantine (#3939) and the PR-less retry hold (#7972/#9239). Each
writes a reason-only record **before** its label edit:

```text
<!-- loom:park Blocked by: (unstated) by=daemon at=2026-10-06T12:00:00Z reason="insta-crash quarantine" -->
<!-- loom:park Blocked by: (unstated) by=daemon at=2026-10-06T12:00:00Z reason="pr-less hold" -->
```

`loom_daemon::sweep_registry::park_hold` owns the format: `DAEMON_HOLD_BY`,
`QUARANTINE_HOLD_REASON`, `PRLESS_HOLD_REASON`, and `is_daemon_hold(&record)`.
A reader that needs to tell a deliberate daemon hold from an undocumented park
should key on `is_daemon_hold`, not on comment prose.

These writers differ from `apply` in two documented ways:

- **A refused body write still applies the label.** For the PR-less hold, the
  label is the deliverable (#9239), and an unparked re-claim loop costs more
  than a park without a name. The fallback is logged at `warn`. A body read or
  write that **times out** stops the writer before its label edit, so a wedged
  `gh` costs one timeout on the `reap_once` read path (#3973).
- **Re-applying a hold replaces that hold's earlier record**, so `at=` dates
  the current park. Releases (`quarantine clear`, the TTL, reconciliation, a
  hand flip back to `loom:issue`) change only labels and leave the record in
  the body. Readers key on `loom:blocked` first, so a leftover record on an
  unblocked issue declares nothing.

### Champion's PR holds (#11861)

Champion's merge-risk and critical-file holds write a reason-only record on
the PR (`reason="champion merge-risk hold"` / `"champion critical-file hold"`,
`by=champion`, `loom_daemon::champion_hold`), keep `loom:pr`, and add
`loom:blocked`. Only Champion or a human releases it. A dependency-only promotion finding writes one record per
open blocker (`park-record apply --blocked-by --by champion`, #11860; or
`classify-dependency-block.sh --check-defer --apply`). Nothing lifts it
automatically when the blockers close: the daemon's release pass was retired
(#11301), so a role or a human clears it.

**A hold is a human evidence gate, not a dependency wait (#10937).** When the
hold's concern names an open issue/PR ("pending real-PDK verification in
#N"), Champion writes one more record beside the reason-only one so
`check-stale-blocked` and the pipeline view show what the PR waits on:

```bash
loom-daemon park-record apply --pr "$PR_NUMBER" --blocked-by "$N" --by champion \
  --reason "champion merge-risk hold: human evidence gate"
```

The reason-only record stays (`body_declares_hold` reads it); `apply` refuses a
closed blocker (#9102), so a hold that names none, or only closed ones, is
unchanged. The extra record is inert: `check_and_unblock_prs` skips a PR whose
`loom-daemon champion-hold classify` says `state=champion-hold` before it reads
a `Blocked by`, so closing #N never lifts the hold. Worked example, PR 8314
holds with `Blocked by: #8301` recorded, #8301 closes:

```
check_and_unblock_prs → PR 8314: state=champion-hold → kept parked, with one notice
```

Release stays Champion's (a release signal, `champion-pr-merge.md` "Sticky
holds") or a human's; nothing auto-releases.

## Who reads one

- `loom-daemon check-stale-blocked` (`defaults/scripts/check-stale-blocked.sh`,
  #8927/#8925) — the pre-wave advisory, **per-repository**: one invocation
  examines the one repository `--repo` / `--repo-root` resolves (#9191). Reads `park_record::blockers` from an
  artifact's body to populate `Evidence::declared`; an artifact whose only
  blocker reference is NOT inside a park record is reported as **PROSE-ONLY**
  (`stale_blocked::undeclared`), separate from **UNDOCUMENTED** (no blocker
  reference anywhere). Its forge reads are batched (#10480: one REST + ETag
  listing, REST blocker reads, one GraphQL query per 100 issues) and run under
  a **budget floor**: after the listing it reads the free `/rate_limit` probe,
  and if the run's projected cost would leave fewer than
  `--min-graphql-remaining` GraphQL points or `--min-core-remaining` core
  requests (default 1000 each; `0` disables) it gathers nothing and reports
  every artifact **NOT EVALUATED**, still exit 0. The same floors are
  re-checked between reads from the forge's own rate-limit answers, so a run
  stops part-way rather than draining the bucket. `--json` adds a
  `forge_cost` object (`graphql_queries`, `graphql_points` from
  `rateLimit.cost`, `rest_requests`, `rest_not_modified`, `budget_before`,
  `projected`, `floor`, `budget_refused`, `budget_stopped`). It first reads
  the repository's `archived` flag (#10562, one REST + ETag read shared with
  the role runner): an archived repository is
  read-only, so nothing is listed, `--json` reports `archived: true` and the
  human report is one line. A probe that fails is NOT EVALUATED, never
  archived and never clear (`archived: null`). Champion's merge-risk hold
  digest issue (exact title, or body starting with its marker) is exempt from
  this pass and the notifier: it is `loom:blocked` only to
  stay out of curation and has no blocker to cite (#9397).
  **Do not loop it over many repositories by hand.** The budget floor reads
  the hourly buckets, which a secondary rate limit never shows in, and a
  one-shot CLI invocation has no rate-limit breaker (it exists only in the
  running daemon), so nothing carries a refusal from one invocation to the
  next. A caller that needs several repositories must pace
  the invocations and stop at the first one that reports a rate-limit refusal
  (it still exits 0, so read the report, not the exit code). Why, and what to
  check instead: [github-authentication.md → Secondary rate limits and
  hand-rolled loops](github-authentication.md#secondary-rate-limits-and-hand-rolled-loops-9191).
- `guide.md`'s `check_and_unblock` / `check_and_unblock_prs` — the active
  unblock sweep. Its `parse_dependencies` reads the park records through
  `loom-daemon park-record parse` — the same code-masked parser as every
  other reader (#13895) — so a marker demoted by `park-record retract`
  declares nothing to it either; the legacy grep path remains only as the
  daemon-unavailable fallback. A dependency stated only in a comment is
  invisible to this sweep by design — see "Problem: Stuck Blocked Issues" in
  `guide.md`.

```bash
# The inverse of render — read the declared blockers back out of a body:
gh issue view 8852 --json body --jq .body | loom-daemon park-record parse
# 8860
gh issue view 8852 --json body --jq .body | loom-daemon park-record parse --json
# {"records":[{"blocker":8860,"by":null,"at":null,"reason":null}],"blockers":[8860],"declared":true}
```

`park-record parse` exits `0` when at least one record was found and `1` when
none was — a shell caller can branch on "is this park declared?" without
parsing output, mirroring `forge check-open-pr`'s exit-code convention. With
`--json`, a body that carries retraction audit lines (`park-record retract`,
below) also reports them under `"withdrawn"` (each with `blocker`,
`blocker_repo`, `by`, `at`, `reason`): a withdrawn blocker is no longer
declared, so it never appears in `blockers`.

## Withdrawing a blocker — `park-record retract` (#13895)

A declared blocker that was later ruled not to gate the artifact would
otherwise keep the park forever: the unblock sweep releases only when *every*
declared blocker closes. Retract withdraws one blocker without deleting the
record or losing provenance:

```bash
loom-daemon park-record retract --issue 8852 --blocked-by 8860 --by guide \
  --reason "ruling 2026-11-15: #8860 is a Curator follow-up, not a gate"
```

On a fresh body read it wraps every live marker naming `--blocked-by` in an
inline code span — the marker's own bytes unchanged, so the history stays
reviewable — which is exactly the demotion `parse` has ignored since #10837,
and appends one visible audit line:

```text
Park withdrawn: #8860 — by=guide at=2026-11-15T12:00:00Z reason="ruling 2026-11-15: #8860 is a Curator follow-up, not a gate"
```

- **Body-only edit.** `loom:blocked` stays on; the caller removes it (or the
  unblock sweep does once the remaining records resolve). Re-parking a
  withdrawn blocker appends a fresh record with `apply --blocked-by`.
- **Idempotent.** No live marker names the ref → exit 0, nothing written.
- **`--file PATH`** (or `-` for stdin) composes against a body in hand instead
  of the forge: offline, it prints the planned body exactly as `--dry-run`
  would and writes nothing — the scratch-body check for a change to the verb
  itself.
- **Refused, nothing written:** a blank `--reason` (a withdrawal that does not
  say why is not an audit trail), or a marker naming the target *and* other
  references (legacy form) — demoting it would silently drop the other
  blockers, so retract each through its own record. An unreadable artifact is
  exit 4. `--dry-run` prints the planned body and writes nothing.
- The audit line is plain text, deliberately without the `Blocked by` phrase
  every dependency parser matches, so the withdrawal itself declares nothing.
  `park-record parse --json` surfaces it under `"withdrawn"`; the reason is
  sanitised exactly like a park record's (`"` → `'`, `--` runs collapsed).
- One known limit of code-span demotion: an unmatched backtick in the marker's
  own paragraph can pair with the inserted span opener and leave the marker
  visible. `retract` checks its own work and refuses rather than report a
  withdrawal that never took effect; hand-edit the marker inside a fenced code
  block in that case.

## The unblock sweep's PR-side functions

`gh issue list` never returns a pull request, so `guide.md`'s
`check_and_unblock` — scoped to issues only — was never a candidate list a
parked PR could appear on at all (#8925's first defect). `check_and_unblock`
calls `check_and_unblock_prs` once, after its own issue loop, to cover the PR
population. The functions below are its full definition, read on demand
from `guide.md`'s "Unblocking Pull Requests (#8925)" section rather than
inlined there (the role-prompt size ratchet: guide.md is installed at two
depths and its whole prompt prefix is frozen at its current size).
Dependency states come from `guide.md`'s shared `resolve_dep_states` (#14710)
— the same `loom-daemon dep-recheck-fingerprint dep-states` resolver the
issue side uses, so the two sweeps cannot disagree about whether a dependency
is terminal.

A frozen PR is skipped during listing. The final PR read checks again for a
freeze before any notice or label edit.

A parked PR's "restore to the queue" differs from an issue's in two ways:
there is no `loom:issue` to restore (a PR was never curated), and the
superseding check reads the PR's OWN state rather than a *linked* PR's — the
parked PR **is** the implementation, so there is nothing else to look up.

```bash
check_and_unblock_prs() {
  local listing limit=1000 focus="${1:-}"
  if [ -n "$focus" ]; then
    listing=$(gh pr view "$focus" --json number,state,body,labels) || return
    listing=$(jq -c '[select(.state == "OPEN" and any(.labels[]; .name == "loom:blocked"))]' <<<"$listing") || return
  else
    listing=$("$GH_READ" pr list --label "loom:blocked" --state open --limit "$limit" --json number,body,labels) || return
  fi
  if [ "$(jq 'length' <<<"$listing")" = "$limit" ]; then
    echo "WARNING: blocked PR listing reached its $limit limit; additional PRs may be unexamined" >&2
  fi
  jq -c '.[] | select(.labels | type == "array" and all(.[]; .name != "loom:frozen"))' <<<"$listing" | while read -r pr_row; do
    local number body records deps dep_verdict resolved_deps='' pr_json trusted hold reason marker detail restore_label
    local head park_hash handoff_marker handoff_status receipt='' reason_only=false
    number=$(jq -r '.number' <<<"$pr_row")
    body=$(jq -r '.body' <<<"$pr_row")
    records=$(printf '%s' "$body" | loom-daemon park-record parse --json) || continue
    deps=$(jq -r '[.records[] | select(.blocker != null)
      | if .blocker_repo then "\(.blocker_repo)#\(.blocker)" else (.blocker | tostring) end]
      | unique[]' <<<"$records") || continue
    if [ -n "$deps" ]; then
      dep_verdict=$(resolve_dep_states "$deps")
      [ "$(sed -n '1p' <<<"$dep_verdict")" = true ] || continue
      resolved_deps=$(sed -n '2p' <<<"$dep_verdict")
    else
      jq -e '.records | length == 1 and .[0].blocker == null' <<<"$records" >/dev/null || continue
      reason_only=true
    fi

    trusted=$(loom-daemon forge trusted-comments --fetch "$number" --with-body) || continue
    jq -e 'type == "array"' <<<"$trusted" >/dev/null || continue
    hold=$(loom-daemon champion-hold classify --pr "$number") || continue
    # Read the PR directly immediately before acting. A new park body, a missing
    # label, a freeze, or a closed PR invalidates the listing snapshot.
    pr_json=$(gh pr view "$number" --json state,body,labels,mergeable,mergeStateStatus,reviewDecision,headRefOid,baseRefOid,isDraft) || continue
    jq -e --arg body "$body" '
      .state == "OPEN" and ((.body | sub("\\n+$"; "")) == $body)
      and any(.labels[]; .name == "loom:blocked") and all(.labels[]; .name != "loom:frozen")
      and has("reviewDecision")
      and (.reviewDecision | IN(null, "", "APPROVED", "REVIEW_REQUIRED", "CHANGES_REQUESTED"))' <<<"$pr_json" >/dev/null || continue
    head=$(jq -r '.headRefOid // ""' <<<"$pr_json")
    park_hash=$(printf '%s' "$body" | git hash-object --stdin) || continue
    handoff_marker="<!-- loom:guide-conflict-handoff head=$head park=$park_hash -->"
    if [ "$reason_only" = true ]; then
      # This limited path never unblocks a mergeable reason-only PR. A checker,
      # merge, or generic green-main observation cannot supply this evidence.
      pr_conflict_snapshot "$pr_json" || continue
      pr_has_reason_only_park "$records" || continue
      records='{"records":[]}'
    fi
    # A prior handoff may have added both Doctor labels while keeping the park.
    # Only our exact trusted marker makes that overlap an expected retry.
    reason=$(pr_has_superseding_block "$hold" "$records" "$trusted" "$pr_json" "$handoff_marker") || continue
    if [ "$reason_only" = true ]; then
      [ "$reason" = merge-conflict ] || continue
      receipt=$(pr_park_clearance_marker "$number" "$head" "$park_hash") || continue
      if ! pr_trusted_marker "$receipt" "$trusted"; then
        printf 'PR #%s: Guide must verify the exact recorded park cause before conflict routing. Receipt key %s\n' "$number" "$receipt"
        continue
      fi
    fi
    if [ "$reason" = merge-conflict ] && pr_conflict_snapshot "$pr_json"; then
      handoff_status=0
      route_parked_pr_conflict "$number" "$pr_json" "$trusted" "$handoff_marker" "$deps" "$receipt" || handoff_status=$?
      case "$handoff_status" in
        0) continue ;;
        3) reason=conflict-route-disabled ;;
        *) continue ;;  # an uncertain or partial transition remains parked
      esac
    fi
    [ "$reason_only" != true ] || [ "$reason" = conflict-route-disabled ] || continue
    case "$reason" in
      unknown) continue ;;
      clear) ;;
      *)
        marker="<!-- loom:guide-pr-superseding:$reason -->"
        if jq -e --arg m "$marker" \
          'any(.[]; any((.body // "" | split("\n"))[]; . == $m))' <<<"$trusted" >/dev/null; then
          continue
        fi
        case "$reason" in
          additional-park-record-*) detail="a separate park reason is recorded in the PR description" ;;
          conflict-route-disabled) detail="Doctor conflict routing is disabled; the conflict still needs an operator's attention" ;;
          *) detail="\`$reason\`" ;;
        esac
        ./.loom/scripts/post-comment.sh "$number" --pr --body "$marker

**Guide kept this PR parked.** The original park cleared${resolved_deps:+ ($resolved_deps)}. The PR still has a superseding block: $detail." || continue
        continue ;;
    esac

    restore_label=$(previous_review_label "$number" "$pr_json") || continue
    gh pr edit "$number" --remove-label "loom:blocked" --add-label "$restore_label" || continue
    ./.loom/scripts/post-comment.sh "$number" --pr --body "🔓 **Unblocked**: Declared blocker(s) resolved ($resolved_deps). Restored \`$restore_label\`."
    echo "Unblocked PR #$number (restored $restore_label)"
  done
}
```

**`pr_has_superseding_block`** — the PR-side transposition of `guide.md`'s
`has_superseding_block`. There is no linked implementation PR to read; the
parked PR's own labels and merge state answer the question instead.
`loom:changes-requested`/`loom:review-requested`/`loom:ci-failure` are
deliberately **excluded** — on a PR those are its normal review-lane state,
not a hold, and removing `loom:blocked` is exactly what hands it back to that
lane:

```bash
pr_has_superseding_block() {
  local hold="$1" records="$2" trusted="$3" pr_json="$4"
  local handoff_marker="${5:-}" additional digest repair_retry=false
  case "$hold" in
    *' state=champion-hold '*' detail=ratification') echo ratification; return ;;
    *' state=champion-hold '*' detail=critical-file') echo champion-critical-file; return ;;
    *' state=champion-hold '*|*' state=stray-operator '*) echo champion-hold; return ;;
    *' state=contradiction '*) echo contradictory-verdict; return ;;
    *' state=stacked-on-loom-branch '*) echo stacked-base; return ;;
    *' state=foreign-park '*|*' state=clear '*) ;;
    *) echo unknown; return ;;
  esac
  if jq -e 'any(.[]; (.body // "") | test("(^|\n)[ \t]*<!-- loom:permanent-block -->[ \t\r]*(\n|$)"))' <<<"$trusted" >/dev/null; then
    echo permanent-hold; return
  fi
  if jq -e '[.[] | select((.body // "" | startswith("<!-- loom:guide-pr-superseding:")
    or startswith("<!-- loom:guide-conflict-handoff ") or startswith("<!-- loom:guide-park-cause-cleared ")) | not)]
    | (last.body // "") | test("(^|\n)[ \t]*<!-- loom:hold-restored -->[ \t\r]*(\n|$)")' <<<"$trusted" >/dev/null; then
    echo restored-hold; return
  fi
  additional=$(jq -c '[.records[] | select(.blocker == null) | .reason] | unique' <<<"$records") || return
  if [ "$additional" != '[]' ]; then
    digest=$(git hash-object --stdin <<<"$additional") || return
    echo "additional-park-record-$digest"; return
  fi
  if [ -n "$handoff_marker" ] && pr_trusted_marker "$handoff_marker" "$trusted" &&
    jq -e '[.labels[].name] | index("loom:merge-conflict") and index("loom:changes-requested")' <<<"$pr_json" >/dev/null; then
    repair_retry=true
  fi
  jq -r --argjson retry "$repair_retry" '
    [ .labels[].name ] as $labels
    | if $labels | any(. == "loom:operator" or . == "loom:operator-only" or . == "loom:operator-decision"
                    or . == "loom:operator-mechanical" or . == "loom:operator-blocked") then "operator-hold"
      elif ($retry | not) and ($labels | index("loom:changes-requested")) and ($labels | index("loom:review-requested")) then "contradictory-verdict"
      elif .reviewDecision == "CHANGES_REQUESTED" then "review-changes-requested"
      elif .mergeable == "CONFLICTING" or .mergeStateStatus == "DIRTY" or .mergeStateStatus == "CONFLICTING" then "merge-conflict"
      elif .mergeable == "MERGEABLE" and (.mergeStateStatus | IN("BLOCKED", "BEHIND", "CLEAN", "DRAFT", "HAS_HOOKS", "UNSTABLE")) then "clear"
      else "unknown" end' <<<"$pr_json" || echo unknown
}
```

The conflict handoff uses the existing Doctor pair `loom:changes-requested`
and `loom:merge-conflict`. It records Guide's decision, applies the pair while
the park is still in force, then lifts the park after a fresh verification.
It never issues a Judge verdict. A trusted handoff marker lets Guide resume an
interrupted transition for the same head and park. A disabled lane retains
the park and records a superseding reason for the operator.

```bash
pr_trusted_marker() {
  jq -e --arg marker "$1" '
    any(.[]; .number == null and ((.body // "") | split("\n") | any(. == $marker)))' \
    <<<"$2" >/dev/null
}

pr_conflict_snapshot() {
  jq -e '
    .state == "OPEN" and .isDraft == false and .mergeable == "CONFLICTING"
    and (.mergeStateStatus | IN("DIRTY", "CONFLICTING"))
    and (.headRefOid | test("^[0-9a-f]{40}$")) and (.baseRefOid | test("^[0-9a-f]{40}$"))
    and any(.labels[]; .name == "loom:blocked")
    and all(.labels[]; (.name | IN("loom:pr", "loom:frozen", "loom:operator", "loom:operator-only",
      "loom:operator-decision", "loom:operator-mechanical", "loom:operator-blocked", "loom:sequenced",
      "loom:reviewing", "loom:treating") | not))
    and has("reviewDecision") and (.reviewDecision | IN(null, "", "APPROVED", "REVIEW_REQUIRED"))' \
    <<<"$1" >/dev/null
}

pr_has_reason_only_park() {
  jq -e '.records | length == 1 and (.[0] | .blocker == null and (.by | IN("judge", "doctor", "curator", "guide"))
    and (.at | type == "string") and .transient == null and
    (.reason | type == "string" and length > 0 and (ascii_downcase | contains("ci-gate") | not)))' \
    <<<"$1" >/dev/null
}

pr_park_clearance_marker() {
  local number="$1" head="$2" park="$3" events event
  events=$(gh api --paginate "repos/{owner}/{repo}/issues/${number}/events?per_page=100" --jq \
    '.[] | select((.event == "labeled" or .event == "unlabeled") and .label.name == "loom:blocked") | "\(.event) \(.id)"') || return 1
  event=$(tail -1 <<<"$events")
  [[ "$event" =~ ^labeled\ [0-9]+$ ]] || return 1
  printf '<!-- loom:guide-park-cause-cleared head=%s park=%s event=%s -->\n' "$head" "$park" "${event#labeled }"
}

pr_record_park_clearance() {
  local number="$1" expected="$2" evidence_file="$3" pr_json body records trusted hold head park marker evidence
  [[ "$number" =~ ^[0-9]+$ ]] && [ -s "$evidence_file" ] || return 1
  evidence=$(cat "$evidence_file") || return 1
  [ -n "$evidence" ] || return 1
  pr_json=$(gh pr view "$number" --json state,body,labels,mergeable,mergeStateStatus,reviewDecision,headRefOid,baseRefOid,isDraft) || return 1
  pr_conflict_snapshot "$pr_json" || return 1
  body=$(jq -r '.body' <<<"$pr_json") || return 1
  records=$(printf '%s' "$body" | loom-daemon park-record parse --json) || return 1
  pr_has_reason_only_park "$records" || return 1
  trusted=$(loom-daemon forge trusted-comments --fetch "$number" --with-body) || return 1
  jq -e 'type == "array"' <<<"$trusted" >/dev/null || return 1
  hold=$(loom-daemon champion-hold classify --pr "$number") || return 1
  [ "$(pr_has_superseding_block "$hold" '{"records":[]}' "$trusted" "$pr_json")" = merge-conflict ] || return 1
  head=$(jq -r '.headRefOid' <<<"$pr_json") || return 1
  park=$(printf '%s' "$body" | git hash-object --stdin) || return 1
  marker=$(pr_park_clearance_marker "$number" "$head" "$park") || return 1
  [ "$marker" = "$expected" ] || return 1
  if ! pr_trusted_marker "$marker" "$trusted"; then
    ./.loom/scripts/post-comment.sh "$number" --pr --body "$marker

**Guide verified the recorded park cause cleared.**

$evidence" || return 1
  fi
  check_and_unblock_prs "$number"
}

route_parked_pr_conflict() {
  local number="$1" snapshot="$2" trusted="$3" marker="$4" config=.loom/config.json
  local deps="$5" receipt="$6" setting after head same hold body park current resolved
  setting=$(printf '%s\n' "${LOOM_REVIEW_CONFLICT_RECONCILE:-}" | tr '[:upper:]' '[:lower:]' | xargs) || return 1
  case "$setting" in 0|false|no|off) return 3 ;; esac
  if [ -f "$config" ]; then
    setting=$(jq -r '.autonomous.roleRunner.roles | if . == null then true else any(.[]; . == "doctor") end' "$config") || return 1
    [ "$setting" = true ] || return 3
  fi
  head=$(jq -r '.headRefOid' <<<"$snapshot") || return 1
  if ! pr_trusted_marker "$marker" "$trusted"; then
    ./.loom/scripts/post-comment.sh "$number" --pr --body "$marker
<!-- loom:base-conflict flagged -->

**Guide verified the original park cleared.** The remaining base conflict at \`$head\` goes to Doctor via \`loom:changes-requested\` and \`loom:merge-conflict\`. The park is kept until the lane labels are confirmed." || return 1
  fi
  gh pr edit "$number" --add-label "loom:changes-requested" --add-label "loom:merge-conflict" || return 1
  after=$(gh pr view "$number" --json state,body,labels,mergeable,mergeStateStatus,reviewDecision,headRefOid,baseRefOid,isDraft) || return 1
  pr_conflict_snapshot "$after" || return 1
  same=$(jq -nr --argjson old "$snapshot" --argjson after "$after" '
    ($old | del(.labels)) == ($after | del(.labels)) and
    ([$old.labels[].name, "loom:changes-requested", "loom:merge-conflict"] | unique) == ([$after.labels[].name] | unique)') || return 1
  [ "$same" = true ] || return 1
  trusted=$(loom-daemon forge trusted-comments --fetch "$number" --with-body) || return 1
  jq -e 'type == "array"' <<<"$trusted" >/dev/null || return 1
  hold=$(loom-daemon champion-hold classify --pr "$number") || return 1
  [ "$(pr_has_superseding_block "$hold" '{"records":[]}' "$trusted" "$after" "$marker")" = merge-conflict ] || return 1
  if [ -n "$receipt" ]; then
    body=$(jq -r '.body' <<<"$after") || return 1
    park=$(printf '%s' "$body" | git hash-object --stdin) || return 1
    current=$(pr_park_clearance_marker "$number" "$head" "$park") || return 1
    [ "$current" = "$receipt" ] && pr_trusted_marker "$receipt" "$trusted" || return 1
  else
    resolved=$(resolve_dep_states "$deps") || return 1
    [ "$(sed -n '1p' <<<"$resolved")" = true ] || return 1
  fi
  gh pr edit "$number" --remove-label "loom:review-requested" --remove-label "loom:blocked"
}
```

When the sweep prints a reason-only candidate, Guide checks the PR's exact
recorded cause. If concrete evidence confirms its recovery, save that evidence
and its sources in a file and call
`pr_record_park_clearance "$number" "$receipt_key" "$evidence_file"` with the
key printed for the candidate. The same Guide pass supplies the trusted note
and reruns just that PR. A changed head, park body, or label episode requires
a new verification. Leave the park in place if evidence is unavailable. An
unnamed `ci-gate` park belongs to its own recovery pass. A passing run on main
alone cannot establish recovery of another actor's permission or log-read failure.

**`previous_review_label`** — which review-lane label to restore
(`loom:review-requested` or `loom:changes-requested`). Keep the one review lane
already present. When neither is present, read the label event history for the
more recent of the two labels ever applied. An empty event history defaults to
Judge and an unreadable history leaves the park in place.

```bash
previous_review_label() {
  local number="$1"
  local label
  label=$(jq -r '[.labels[].name | select(. == "loom:review-requested" or . == "loom:changes-requested")]
    | if length == 1 then .[0] else empty end' <<<"$2") || return
  if [ -n "$label" ]; then
    echo "$label"
    return
  fi
  label=$(gh api --paginate "repos/{owner}/{repo}/issues/${number}/events?per_page=100" --jq \
    ".[] | select(.event == \"labeled\" and (.label.name == \"loom:review-requested\" or .label.name == \"loom:changes-requested\")) | .label.name" \
    2>/dev/null) || return
  label=$(tail -1 <<<"$label")  # the per-issue event listing ascends oldest first
  if [ "$label" = "loom:changes-requested" ]; then
    echo "loom:changes-requested"
  else
    echo "loom:review-requested"
  fi
}
```

```bash
# PR #8314 has loom:blocked, body contains "<!-- loom:park Blocked by: #8322
# by=doctor at=2026-09-19T12:09:00Z reason=\"needs an architecture ruling\" -->"
# (a park record, not a comment).
```

Use `loom-daemon check-stale-blocked --repo OWNER/REPO --pr-resweep --limit 1000`
for a one-off, read-only report. Add `--json` for the namespaced resweep rows.
It distinguishes releasable named parks, a current conflict whose repair is a
separate step, still-open dependencies, held parks and unreadable data. Unnamed
parks need the cause review above. `dependent_issues` names parked same-repo
issues that declare a PR eligible for the conflict handoff as their blocker.
A releasable snapshot still goes through Guide's
fresh PR and review checks. The report reads the current PR state, labels and
formal review decision before reporting an eligible park. Incomplete state is
reported as unevaluated. The report performs only forge reads.

## What this format does not do

It never reads the forge and never writes a label. Rendering is the
responsibility of the role applying the park; parsing is for whoever later
asks whether the park still holds. Deciding whether a cleared park should
actually be unparked is `guide.md`'s `check_and_unblock`/`check_and_unblock_prs`
job (issues) and `check-stale-blocked`'s advisory report (both issues and
PRs) — this document defines the wire format both sit on top of, nothing more.

One mechanical carve-out (#13331): when a merge clears the blockers of an
**issue** whose park records are all `by=curator`, each naming a blocker, and no
other blocker, unticked dependency, or hold label remains,
`loom-daemon notify-cleared-blockers` removes `loom:blocked`, adds
`loom:curated` (never `loom:issue`), and says so in its cleared-blocker comment.
`by=` is self-declared, which is accepted because the action approves nothing.

See also: [`label-state-machine.md`](label-state-machine.md) for where
`loom:blocked` sits relative to `loom:operator`/`loom:frozen`, and
[`lease-record.md`](lease-record.md) for the sibling HTML-comment-marker
convention this format's shape was co-designed with.

## `park-record released` (#12665)

`loom-daemon park-record released --pr N [--entered-at TS] [--failed]` writes
nothing to the forge. Champion calls it after removing a merge-risk hold's
`loom:blocked`, to journal the release as a `hold.transition` `remove`
([`telemetry-schema.md`](telemetry-schema.md#holdtransition--a-hold-label-applied-to-or-removed-from-a-pr)).
A Champion `park-record apply` journals the matching `add` itself, only when
the label was not already on the PR.

## Transient parks — `park-record apply --transient <cause>` (#13606)

A park whose cause clears by itself (for example `batch_no_capacity` from the
Spot batch fleet) carries a retry time instead of waiting for a person:

```text
<!-- loom:park Blocked by: (unstated) by=builder at=2026-11-05T12:00:00Z transient=capacity:batch attempt=1 until=2026-11-05T12:30:00Z -->
```

- `--transient` is mutually exclusive with `--blocked-by`; it counts as the
  written choice, so no `--reason` is needed.
- `attempt` is the previous record for the same cause plus one (else 1).
- Delay: 30 min, 1 h, 2 h, 4 h, … capped at 24 h, with up to ±10% jitter
  (`TRANSIENT_*` constants in `park_record.rs`).
- Re-running while `until` is in the future is a no-op; after it passes, a
  re-park appends the next attempt.
- A record without these attributes parses exactly as before. A transient
  record with a missing or unparseable `until` is treated as already due.

Release: Guide's unblock sweep (`release_due_transient_parks`) reads
`park-record parse --json` (`records[].transient` = `cause`, `attempt`, `until`,
`due`, `escalate`; `null` for a legacy park) and removes `loom:blocked` once
`due`. Only the last record counts, so a later blocker or reason park wins. At
`attempt >= 6` or park age >= 7 days it posts one escalation comment
(`<!-- loom:transient-escalated cause=… -->`) and keeps retrying at the 24 h cap;
it never adds a hold. The record stays in the body so the next re-park
increments `attempt`. Release has no `hold.transition` span: `park-record
released` is PR-only, so cause and attempt are in the release comment.
