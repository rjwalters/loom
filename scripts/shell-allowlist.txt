# shell-allowlist.txt — every `.sh` this repo owns, with the reason it is shell.
#
# Policy (issue #7762, ADR-0018): new executable logic goes into Rust as a
# `loom-daemon` subcommand. New shell is admissible only with a reason from the
# closed category list below, and `check-shell-allowlist.sh` fails when a
# tracked `.sh` file exists that is not listed here. Full rationale, the
# category definitions, and the four objections this settles:
# .loom/docs/shell-language-policy.md.
#
# Format:  <path>  <category>  <reason>
# The first whitespace-delimited token is the repo-relative path, the second is
# the category, everything after it is the (required) one-line reason. Blank
# lines and lines beginning with `#` are ignored.
#
# Categories (these are #7758's categorical verdicts — do NOT invent a second
# taxonomy):
#
#   bootstrap    Runs before a loom-daemon binary is available (or after it is
#                removed). Requiring the binary to install itself is circular.
#   hook-entry   A hook (PreToolUse/SessionStart) needs a shell-invocable
#                command. The stub stays; the logic behind it is a port target.
#   vendored     Canonical copy lives in rjwalters/repo and is re-vendored at
#                release. Structural change goes upstream, not here.
#   stub         Shape-A stub: <40 code lines AND its last code line is `exec`.
#                This is the trivial-glue cap, and it is MACHINE-CHECKED — an
#                entry claiming `stub` that exceeds either half of that test
#                fails the gate, so the category cannot become a rubber stamp.
#   test         Shell because its subject is shell. Follows its subject; never
#                an independent reason to keep either in shell.
#   contract     An existing invocation contract: the file's *name* is consumed
#                by role prompts, CI workflows, hooks, or consumer repos.
#                BASELINE-ONLY — see the section markers below.
#   settled      Shell we are deliberately KEEPING (#8237): it works, its blast
#                radius is small, and nobody intends to port it. Distinct from
#                `bootstrap`/`vendored`, which are claims a file *cannot* be
#                Rust; this is a claim it *will not be*. MACHINE-CHECKED on both
#                halves, every run: zero fix-commits in the trailing six months
#                (the same window and the same fix/revert/hotfix test the
#                shell-budget churn report uses) AND no irreversible operation
#                anywhere in the file. Membership is therefore a rolling
#                measurement, not a verdict — the moment a settled script takes
#                a fix, the gate fails and the entry goes back to `contract`.
#                A settled file may SHRINK but never GROW (no override), and
#                the progress report counts it alongside `portable` so moving a
#                script here cannot improve `net vs epic start`. BASELINE-ONLY,
#                for the same reason `contract` is: a file with no history has
#                zero fixes only vacuously.
#
# Why some quiet scripts are NOT settled — do not re-propose them. Of the 71
# portable-pool scripts with zero fix-commits in the window, 26 (4,753 lines)
# perform an irreversible operation and stay `contract` on purpose.
# `loom-stop.sh`, `provision-codex-hooks.sh`, `run-job.sh` and friends are quiet
# AND able to destroy data; quiet is not the same as safe, and a rarely-exercised
# script with a latent data-loss bug is worse, not better, because nothing has
# forced the bug into the open yet. The screen is deliberately crude and
# asymmetric: a false positive costs nothing (the script simply stays in scope),
# a false negative admits a script that can delete your work.
#
# The other 45 are ELIGIBLE, which is not the same as settled — both halves are
# necessary conditions, and the category is still a statement that nobody
# intends to port the file. The initial population is the 44 of them categorised
# `contract`. The 45th, defaults/scripts/lib/installed-file-guard.sh, is
# `hook-entry` and its own entry below says it "ports with" the two PreToolUse
# entry points it backs — an active port target with a known destination shape
# is not shell we are deliberately keeping. Nothing forces an eligible script
# here: the gate refuses a `settled` entry that has stopped qualifying, never a
# `contract` entry that would qualify. Staying in scope is always allowed.
#
# Scope: `git ls-files '*.sh'`, minus `.loom/**`. `.loom/scripts` is a symlink
# to `defaults/scripts` in this repo and a resync copy downstream, and
# `.loom/hooks/*.sh` is a tracked resync copy of `defaults/hooks/*.sh` kept
# honest by check-hooks-defaults-parity.sh — listing either would double-count
# every entry against its `defaults/` source. Both are governed at that source.
#
# Two sections, and the difference is enforced:
#
#   @section baseline — the files that existed on `main` when #7762 landed.
#     Nothing was migrated to build it; the list records the state as found, so
#     a NEW file cannot hide in it. Do not append here.
#   @section new — everything added after the policy. `contract` and `settled`
#     are NOT valid categories in this section: neither "something already calls
#     it by name" nor "it has needed no fix in six months" can be true of a file
#     that did not exist yet. A new `.sh` must be bootstrap, hook-entry,
#     vendored, stub, or test — or it is a loom-daemon subcommand.
#
# The ratchet on the SIZE of the files listed here is a separate mechanism
# (#7711, scripts/check-file-size-budget.sh). This file says nothing about how
# big any of them may be, and nothing here is a migration mandate.
